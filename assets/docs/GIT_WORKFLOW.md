# Git Workflow Guide - Avoiding manifest.json Conflicts

## The Problem

`manifest.json` is auto-generated by GitHub Actions. When you commit locally and GitHub Actions runs at the same time, you get merge conflicts.

## The Solution: Use These Commands

### Recommended Workflow

```bash
# Step 1: Sync with remote (handles conflicts automatically)
git clean-sync

# Step 2: Make your changes, then commit (checks for conflict markers)
git smart-commit "Your commit message"

# Step 3: Push
git push
```

### What Each Command Does

**`git clean-sync`**:
- Stashes your changes
- Pulls latest (with rebase)
- Auto-resolves `manifest.json` conflicts (uses remote version)
- Restores your changes
- Checks for any remaining conflict markers and cleans them

**`git smart-commit "message"`**:
- Checks for conflict markers in `manifest.json` before committing
- If found, automatically cleans them (uses remote version)
- Adds all files
- Commits with your message
- Safe to use anytime

## Alternative: Simple Two-Step

If you prefer simpler:

```bash
# Step 1: Sync
git clean-sync

# Step 2: Normal commit (but it will check for conflicts)
git add .
git commit -m "Your message"
git push
```

## Why Conflicts Happen

1. You commit locally → `manifest.json` gets your timestamp
2. GitHub Actions runs → Updates `manifest.json` with new timestamp
3. You pull → Git sees both versions → Conflict!

## The Fix

- `.gitattributes` tells Git to prefer remote version during merges
- `git clean-sync` automatically resolves conflicts
- `git smart-commit` prevents committing conflict markers

## If You See Conflict Markers

If you ever see `<<<<<<< Updated upstream` in `manifest.json`:

```bash
# Quick fix:
git checkout --theirs assets/js/manifest.json
git add assets/js/manifest.json
```

Or just run `git clean-sync` - it handles it automatically!
