## Data Flow Verification

### 1. Login Flow
```
index.html (payment-lookup.js)
  → Lookup in manifest.json
  → Store jobId, jobPath, jobData in sessionStorage
  → Redirect to /{jobId}
  → 404.html detects jobId, loads job.html template
  → job.html initializes, calls PaymentRouter.determineRoute()
  → Routes to appropriate section (#contract, #invoice, #payment-1, etc.)
```

### 2. Contract Signing Flow
```
contract-controller.js
  → User signs contract
  → POST /api/sign-contract
  → Triggers GitHub Actions workflow_dispatch (orchestrate.yml)
  → orchestrate_workflow.py calls update_state.py (action: sign-contract)
  → Updates contract.signatures in JSON
  → Commits and pushes
  → Frontend updates state, routes to invoice
```

### 3. Payment Flow
```
checkout-controller.js
  → User clicks "Pay"
  → POST /api/create-checkout-session (on-demand)
  → Creates Stripe Checkout Session
  → Redirects to Stripe hosted checkout
  → User completes payment
  → Stripe webhook: checkout.session.completed
  → api/webhook.js receives event
  → Triggers GitHub Actions workflow_dispatch (orchestrate.yml)
  → orchestrate_workflow.py calls update_state.py (action: update-payment)
  → Updates state_management.[initial|balance]_payment_intent.succeeded
  → Commits and pushes
```

### 4. Stripe Catalog Sync Flow
```
Push to assets/jobs/*.json
  → GitHub Actions triggers orchestrate.yml (push event)
  → orchestrate_workflow.py calls sync_catalog.py
  → Compares filenames to manifest.json entries
  → Creates/updates Stripe Products, Prices, Customers, Coupons
  → Stores Stripe IDs in state_management.object
  → Calls generate_manifest.py
  → Commits and pushes all changes
```

### 5. Tracking Events Flow
```
contract-controller.js / invoice-controller.js
  → User action (contract loaded, scrolled, invoice viewed, download)
  → POST /api/track-event
  → Triggers GitHub Actions workflow_dispatch (orchestrate.yml)
  → orchestrate_workflow.py calls update_state.py (action: track-event)
  → Updates state_management.client_status
  → Commits and pushes
```

## API Endpoint Verification

### ✅ create-checkout-session.js
- Creates Checkout Sessions on-demand (per CHECKOUT_SESSION_DETAILS.md)
- Accepts: `price_id`, `coupon_id`, `customer_id`, `job_id`, `payment_number`, `return_url`
- Returns: `session_id`, `session_url`
- Sets 24-hour expiration
- Includes metadata: `job_id`, `payment_number`

### ✅ sign-contract.js
- Triggers workflow_dispatch with action: `sign-contract`
- Payload: `{ signatures: { client: {...}, contractor: {...} } }`

### ✅ update-payment.js
- Triggers workflow_dispatch with action: `update-payment`
- Payload: `{ payment_number: 1|2, succeeded: ISO timestamp }`

### ✅ track-event.js
- Triggers workflow_dispatch with action: `track-event`
- Payload: `{ event_type: string, event_data: object }`

### ✅ webhook.js
- Listens for `checkout.session.completed`
- Extracts `job_id` and `payment_number` from metadata
- Triggers update-payment workflow

## Workflow Verification

### ✅ orchestrate.yml
- Trigger: `push` (on assets/jobs/*.json changes)
- Trigger: `workflow_dispatch` (for API-triggered actions)
- Inputs: `action`, `job_id`, `payload`
- Single job that runs orchestrate_workflow.py
- Handles all automation in one place

### ✅ orchestrate_workflow.py
- Routes to appropriate scripts based on trigger/action
- Batches all JSON updates before committing
- Single git push at end (prevents cancellation issues)
- Error handling and logging
