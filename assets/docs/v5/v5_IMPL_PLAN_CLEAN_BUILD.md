# v5 Implementation Plan: The "Clean Build" 💎

## The Vision
Stop patching the "Frankenstein". Build a fresh, focused payment experience using the knowledge we have now.

**Core Concept**: 
Move from **Python-Baked HTML** -> **Static Shell + Dynamic JSON**.

## Architecture Comparison

| Feature         | Current (v4)                         | v5 (Clean Build)                         |
| :-------------- | :----------------------------------- | :--------------------------------------- |
| **Serving**     | `[uuid].html` (Generated by Python)  | `index.html` (Static App Shell)          |
| **Data Source** | Hardcoded in HTML + `sessionStorage` | Fetched from `assets/jobs/[uuid].json`   |
| **Routing**     | `FlowManager` hiding/showing DIVs    | `FlowEngine` rendering simple components |
| **Updates**     | Requires rebuilding HTML via Python  | Instant (Update JSON only)               |
| **Deployment**  | Python Build Script                  | Git Push (Static Files)                  |

## The v5 Stack
1.  **Static Shell (`index.html`)**: 
    *   Contains the "Foggy Glass" layout structure.
    *   Empty containers for content.
    *   Loads `v5-loader.js`.
2.  **Data Layer (`/jobs/[id].json`)**:
    *   Strict Schema (already defined in `user_behavior.py`).
    *   Python workflow *only* updates this JSON. It stops touching HTML.
3.  **Engine (`v5-engine.js`)**:
    *   Reads URL param `?job=uid-xyz`.
    *   Fetches JSON.
    *   Renders the current step (Contract/Invoice/Pay) into the glass container.
4.  **No Routers**:
    *   The state *is* the JSON. If JSON says "paid", engine shows "Success".

## Migration Step-by-Step
1.  **Create Shell**: Build `v5/index.html` (Pure HTML/CSS, no Python templating tags).
2.  **Port Engine**: Simplify `FlowManager` into `v5-engine.js` (Fetch JSON -> Render).
3.  **Port Components**: Move the specific logic from `contract-controller` etc into pure render functions.
4.  **Update Workflow**: Modify `admin_push.py` and `user_behavior.py` to **STOP** creating `[id].html`. Just upload `[id].json`.

## Why this is faster
*   **Zero Build Time**: Change HTML/JS -> Refresh Browser. No `admin_push.py` loop.
*   **Separation of Concerns**: Python handles Data. JS handles UI. No mixing.
*   **Debuggability**: You can inspect the JSON directly to see the state.
