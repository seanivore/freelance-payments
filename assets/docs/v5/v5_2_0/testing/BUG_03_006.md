## Bug_03_006: BG Media Missing in PDF Viewer

  + This is a variant that has arisen after the fix was applied for **Bug_03_001: BG Media Not Found In Console Logs**

**EXPECTED BEHAVIOR**: 

  1. Load homepage, see background art 
  2. Login, get sent to contract or balance view, see background art in PDF viewer 
  3. Expected behavior is the same on various devices.

**ACTUAL BEHAVIOR**: 

Login homepage has background art. When logging in as a new user seeing contract, and returning user seeing balance page, the background art seems to be missing from the PDF viewer. This is true on desktop and mobile. 

**BUG DETAILS**: 

When you scroll extra far on MacOS and iOS devices, it lets you pull down the canvas/div above the background, and see behind the element. This typically shows the website page's set background. 

When you do this on either device, in either documents being viewed by the PDF viewer, you can see an image behind the dark window that is the PDF viewer. I've shown this in the referenced images.

It appears that the viewer's back window section is the culprit. The CSS class `bg-portfolio-bg-primary` is set to a dark background color. In the first example I turned off the "background-color" property completely and was able to see the background art nicely. In the second example I set the opacity to 0.2 and was able to see the background art equally nicely.

```css 
.bg-portfolio-bg-primary {
    --tw-bg-opacity: 1;
    /* background-color: rgb(31 31 31 / var(--tw-bg-opacity, 1)); */ 
  }
```

**OR**

```css 
.bg-portfolio-bg-primary {
    --tw-bg-opacity: 0.2;
    background-color: rgb(31 31 31 / var(--tw-bg-opacity, 1));
  }
```

Further, I turned off the .backdrop-blur-sm class's property "--tw-backdrop-blur: blur(4px);" and it gave the top toolbar a nicer, semi-transparent look. I did this on a whim while looking to give the toolbar a nice drop shadow to create some depth making it look like it is floating above the PDF paper.

Note that the "-webkit-backdrop-filter" property is not working for whatever reason. I don't know what it is doing, but it is all crossed out, and regardless it looks nice without it. 

```css 
.backdrop-blur-sm {
    /* --tw-backdrop-blur: blur(4px); */
    -webkit-backdrop-filter: var(--tw-backdrop-blur) var(--tw-backdrop-brightness) var(--tw-backdrop-contrast) var(--tw-backdrop-grayscale) var(--tw-backdrop-hue-rotate) var(--tw-backdrop-invert) var(--tw-backdrop-opacity) var(--tw-backdrop-saturate) var(--tw-backdrop-sepia);
    backdrop-filter: var(--tw-backdrop-blur) var(--tw-backdrop-brightness) var(--tw-backdrop-contrast) var(--tw-backdrop-grayscale) var(--tw-backdrop-hue-rotate) var(--tw-backdrop-invert) var(--tw-backdrop-opacity) var(--tw-backdrop-saturate) var(--tw-backdrop-sepia);
  }
```

Finally, I adjusted the border-bottom-width to 2px, adjusted its opacity to .2, and its RGB color to rgb(192 189 189 / 34%). This made the border equally as prominent, but more realistic looking. 

I then added a filter property to drop-shadow(2px 4px 6px #0f0f0f47) and it gave the toolbar a nice drop shadow to create some depth making it look like it is floating above the PDF paper. The default it populated for the shadow was very intense, so please also note these settings for a realistic shadow for toolbar over PDF paper. 


```css 
.border-portfolio-border {
    --tw-border-opacity: .2;
    border-color: rgb(192 189 189 / 34%);
    border-bottom-width: 2px;
    filter: drop-shadow(2px 4px 6px #0f0f0f47);
}
```

I detailed these changes carefully above so that you can take those settings and apply them to anywhere else in the CSS file that it makes sense to do so based on the reasoning I provided for making the changes.
