### Questioning Git Push Logic 

* **What we have been doing, and the rules we've been following are SIMPLE**

  1. Admin user only ever creates **NEW** JSON files 
    - We create new job JSON files 
    - We delete mistake job JSON files 
    - We **DO NOT EVER UPDATE** existing JSON files other than deletion 
    - It always comes from this machine, local to remote 
    - There is no instance where conflict occurs 
    - New files output into `admin-push.yml` workflow should always be considered GOLD and MOST CURRENT of that JSON file 
  2. The `admin-push.yml` workflow automation only ever **UPDATES EXISTING** JSON files 
    - These are only ever done in one batch at a time 
    - They never come from this machine 
    - They **NEVER** create new JSON files 
    - They only **UPDATE** existing JSON files 
    - Workflows never run simultaneously 
    - At the very end of the workflow the new build is deployed, including all JSON files in their state at that time 
    - Therefore, there is NO INSTANCE where conflict occurs 
    - The output at the end of this workflow should always be considered GOLD and MOST CURRENT of that JSON FILE 
  3. The `user-exit-events.yml` workflow automation only ever **UPDATES EXISTING** JSON files 
    - These are only ever done in one batch at a time 
    - They never come from this machine 
    - They **NEVER** create new JSON files 
    - They only **UPDATE** existing JSON files 
    - Workflows never run simultaneously 
    - At the very end of the workflow the new build is deployed, including all JSON files in their state at that time 
    - Therefore, there is NO INSTANCE where conflict occurs 
    - The output at the end of this workflow should always be considered GOLD and MOST CURRENT of that JSON FILE 
  4. The manifest is updated **ONCE** per workflow instance and never updated anywhere else 
    - Remove the "last updated" timestamp at the bottom of the manifest file; we need to simplify 
    - If desired, we could add a timestamp in each job on the manifest for when it was added 
    - Once added to the manifest, A JOB IS NEVER UPDATED until it is deleted from the manifest 
    - Admin literally NEVER touch or edit the manifest file

* **There is no reason for a complex Git Logic to be in place**
